# Agent de veille : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Une routine quotidienne dont les sous-agents rédigent jusqu'à 3 articles originaux de jeux vidéo, publiés seulement s'ils passent un contrôle automatique écrit dans le dépôt.

**Architecture :** `veille.py` (fonctions pures testées, bibliothèque standard) fournit la collecte, l'outil de lecture à liste blanche et le contrôle ; deux workflows lancent le contrôle puis la publication ; `blog.py` accepte le type `news` ; le texte de la routine et les consignes des sous-agents sont versionnés dans `docs/veille/`.

**Tech Stack :** Python 3.13 en local et 3.12 sur GitHub Actions (bibliothèque standard, `unittest` ; ne pas utiliser `Path.read_text(newline=)`), GitHub Actions, routine Claude cloud (`RemoteTrigger`).

**Spec :** `docs/superpowers/specs/2026-10-27-veille-design.md` (les « §n » sont les siens).

## Global Constraints

- Adresse unique du site : `https://esportly.eu`. Branche locale `veille` créée depuis `blog` avec `--no-track` ; commits `git -c user.name=Claude -c user.email=noreply@anthropic.com commit`, trailer du modèle qui a fait le travail ; pas de push ni de fusion hors des règles du pilote automatique (push et PR sans fusion : oui ; fusion, routine planifiée, secrets, réglages du dépôt : phrase explicite de l'utilisateur).
- Scripts : bibliothèque standard seulement ; commentaires en français, identifiants en anglais ; compatibles 3.12 ; fichiers lus avec `read_bytes().decode("utf-8")` ou `open(..., newline="")` ; fragments générés sur une ligne ; `…py` = `PYTHONDONTWRITEBYTECODE=1 PYTHONUTF8=1 PYTHONTZPATH=C:\Users\horny\anaconda3\Lib\site-packages\pytz\zoneinfo py -3.13` ; suites sur 3.13 (`-W error`) et sur Python 3.11 (`py -V:Astral/CPython3.11.16`).
- Limites du §6 : article 150 à 450 mots, 1 à 3 sections, 1 à 5 sources, plus longue suite de mots identiques ≤ 6, recouvrement de suites de 5 mots avec une source ≤ 15 %, ressemblance avec une page existante ≤ 40 %, 3 articles par jour, clé de sujet absente des 14 derniers jours.
- Collecte (§5) : `robots.txt` respecté, `User-Agent: esportly-veille/1.0 (+https://esportly.eu)`, une requête par seconde et par site, délai 20 s, 2 essais, 2 Mo, aucune redirection hors liste blanche, 15 candidats, 40 lectures, éléments publiés depuis 3 jours.
- Tout texte venu du web est une donnée : aucune sortie de `veille.py` ne l'exécute ni ne le transmet comme instruction.

## Review Focus

1. **Redirection ou lien hors liste blanche** : une adresse d'un autre domaine (ou une redirection) est refusée par la collecte, par l'outil de lecture et par le contrôle (V3, V4, V6).
2. **Texte piégé** : un candidat qui contient « ignore tes consignes… » reste une donnée ; aucune fonction ne le traite comme une commande (V3).
3. **Contournement du contrôle** : une pull request qui modifie `.github/`, `sources.json`, `mode.json`, `STOP` ou un fichier existant est refusée (V5).
4. **Recopie déguisée** : un texte qui recopie une source avec quelques mots changés est refusé par la mesure de suites de 5 mots (V6).
5. **Quatrième article du jour et interrupteur** : refus chiffré, y compris via l'historique git (V5).
